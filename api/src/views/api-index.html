Charity Events API

PROG2002 Web Development II — Assessment 3. Node.js + Express + MySQL. Read-only endpoints for the client website, plus the write endpoints that back event registration and the admin website.

Read endpoints — used by the client website
MethodPathPurpose
GET/api/healthService and database health check
GET/apiMachine readable index of this API
GET/api/eventsFiltered list of active events (home + search)
GET/api/events/upcomingCurrent and upcoming events, soonest first
GET/api/events/:idFull detail, tickets and goal progress for one event
GET/api/categoriesCategory filter options with event counts
GET/api/locationsLocation filter options with event counts
GET/api/organizationOrganisation featured on the home page
GET/api/statsHeadline numbers for the home page
Registration endpoints — Assessment 3
MethodPathPurpose
GET/api/events/:id/registrationsRegistrations recorded against one event
POST/api/events/:id/registrationsRegister an attendee for an event
GET/api/registrationsEvery registration, newest first
GET/api/registrations/:idOne registration
PUT/api/registrations/:idChange a registration
DELETE/api/registrations/:idRemove a registration
Admin endpoints — used by the staff website
MethodPathPurpose
GET/api/admin/eventsEvery event, including suspended and cancelled
GET/api/admin/events/:idOne event with its ticket types and registrations
GET/api/admin/reference-dataCategories, locations and organisations for the forms
POST/api/eventsCreate an event
PUT/api/events/:idUpdate an event
DELETE/api/events/:idDelete an event (refused with 409 if it has registrations)
POST/api/admin/eventsCreate an event (same handler)
PUT/api/admin/events/:idUpdate an event (same handler)
DELETE/api/admin/events/:idDelete an event (same handler)
Two write paths, one implementation. The admin website sends its create, update and delete requests to the plain RESTful paths (/api/events), while the /api/admin/events paths exist so the admin website can also GET the events the public API hides. Both sets of write routes call the same controller functions, so there is exactly one implementation of each rule and no chance of the two drifting apart.
Client website: start it separately and open http://localhost:5500/index.html. The admin website is at http://localhost:5500/admin/index.html.
Search example: /api/events?state=all&city=Lismore&category=1&from=2026-09-01
Written with: HTML, CSS and plain JavaScript only (no CSS or JS framework, no templating engine). Express serves this API and nothing else; the pages are static files sent as they are.
